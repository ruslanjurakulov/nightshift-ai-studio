## Prices (the owner's reading, 2026-11-13)

<https://ideogram.ai/pricing/?pricing_tab=api> draws its table with a script that a plain fetch is refused, so the owner read it
in a browser. Ideogram 4.5 Generate has a Low, Medium and High price, the same at 1K and 2K. With source images there is also a
Very Low tier and High is dearer; Precise Edit has the same four tiers; Remix has Low, Medium and High (High dearer with reference
images). The figures are on the vendor pricing page; the prices themselves live in the model registry, not in prose.

The registry stores the three Generate figures as `pricing.variants` by quality, `provider_usd_per_unit` at medium (the tier a
Studio request settles on when it names none: 0060 / 0153), `confirmed: false` and a note that says ESTIMATE. In this repository
`confirmed: true` is kept for a figure a probe's billed amount has matched.

## What was built, and why each choice

- **Text to image only.** The same endpoint edits when `images` are uploaded, but its High tier then costs more than the text-to-image High. A
  registry entry has one tier table, and 0153 prices a preview from it by tier alone, so an edit at High would be quoted at the
  text-to-image figure. Edit, precise edit and remix stay out until a separate entry (or a per-capability price) can say the edit price.
- **The tier is always sent, and only the priced one.** Left out, Ideogram renders a text-only request at `high`, dearer
  than the medium a request without a tier is quoted at. Our tiers map one to one onto the vendor's values: `low -> low`,
  `medium -> medium`, `high -> high`. `very_low` is not offered (it "requires source images"). A request with no tier, or any other
  tier, is refused before anything is sent (`not_accepted`), never replaced.
- **No `size` is sent; the registry offers no shape** (as `ideogram-4`). The 4.5 page names its 1K/2K presets only by example, so
  sending a 16:9 size would be a guess. The vendor's documented default, `auto`, picks the shape from the prompt and bills as 2K;
  the owner's table gives one figure for "1K/2K" at each tier. A request naming a shape is refused rather than dropped.
- **`num_images` is sent as 1.** The price is per image; the vendor's default is 1, but the call does not depend on it.
- **Multipart, synchronous, timeout 180 s.** Multipart is the encoding the OpenAPI schema describes (the existing Ideogram
  adapters send it the same way). The call waits for the image ("Higher quality takes longer").
- **Error mapping.** 401 -> `auth`; 402 / 429 with `reject_reason` `inflight_limit` -> `rate_limited` (wait and retry); any other
  documented `reject_reason` (balance, subscription, daily cap, feature or app-user limit) -> `quota`, because retrying only fails
  again; 422 -> `policy` (documented as a safety refusal; HTTP 422 would otherwise read as a bad request); `is_image_safe: false`
  -> `policy`; a 2xx without an image -> `bad_response` marked "the vendor may have billed". Vendor text is scrubbed of every key.
- **Terms**: the same Ideogram Developer API Agreement 2.3.3 note and "Powered by Ideogram" attribution as Ideogram 3 and 4;
  `api_exposure: web_only`.

## What is not verified

- No call has been made. The probe (`ideogram-4.5`, low tier) is the first real call; until it succeeds the model stays hidden
  and 0139 refuses the preview.
- The prices are the owner's browser reading, not an invoice. A free check exists: the same request with `?dry_run=true` returns
  Ideogram's own `PriceQuote` without generating or billing (needs the key; not done here).
- Whether `auto` really bills as 2K at the same figure as 1K rests on the "1K/2K" wording of the price table.
- Seen while reading, not changed here: `ideogram-4`'s adapter calls the v1 path `/v1/ideogram-v4/generate` with `text_prompt`,
  which v1's index now calls "legacy"; v2's equivalent is `/v2/image/generate/ideogram-4` with `prompt`. Its probe will tell.
