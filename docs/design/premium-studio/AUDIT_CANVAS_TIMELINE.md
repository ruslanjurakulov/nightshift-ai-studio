## Verified current gaps

1. **Navigation is not synchronization.** Sketch Canvas lacks a Film identity; its node/wire localStorage document is unrelated to the Film Timeline's database read model. No authoritative Canvas-node ↔ Film-scene/take mapping appears in these sources. A Canvas|Timeline switch alone cannot imply shared project content.
2. **Draft graph and execution history differ.** A Canvas node points to one latest creative job and output; Film already has versioned take history. Adding generation history to a second graph store would duplicate existing concepts. Full form configuration is not covered by `CanvasNode.draft`.
3. **Not every desired timeline operation exists.** Current Film Timeline can reorder scenes and save two levels, while effects/ambience lanes lack persistence. Arbitrary trim/slip/overlap/keyframe edits cannot be written back by pretending they are scene order. Reuse the full existing editor for operations its schema supports; make round-trip limits visible.
4. **Uploads are partly wired, not a universal imported-take feature.** Existing graph asset nodes and media library references can supply generation inputs; Film has first/last-frame image references and music asset. Arbitrary uploaded video as a chosen Film scene take, uploaded narration selection and external creative-job adoption need explicit backend validation and attachment semantics. Do not manufacture completed takes client-side or silently trigger another paid generation to import a file.
5. **Main Timeline misrepresents requested duration as measured.** `lib/studio/timeline.ts:119–123` picks only the first completed shot, without verifying all shots/highest attempts; `:158–169` uses take `durationS` as measured. Existing assembler selection is stricter. PR793 addresses this; see below.
6. **Main confirmation and save race fixes are pending.** `AssemblePanel.tsx:160–162` lets the main key start when already confirming and retries a failed network request without reopening confirmation. Timeline sliders do not share a serialized/debounced mutation path with scene reorders (`StudioTimeline.tsx:194–248`). Proposed UI integration must inherit reviewed corrections rather than preserve these behaviors.

## Minimal integration proposal for approval

Use **Film as the durable project identity**. Keep standalone personal sketches supported; offer an explicit “Save sketch into project” or attach-to-existing-project action. Import validates every referenced asset/job as the signed-in member and displays unsupported nodes before any write. Opening a project routes all three views through its Film ID and one project controller.

Retain `CanvasState`, `canWire`, `connect` and board rendering as the graph model. Persist only the missing Film-owned graph document and stable scene/take bindings, with bounded schema version and an optimistic graph revision. This is a proposed extension to existing Film persistence, **not an approved table or migration**. Prefer one validated Film-owned metadata field/document if reviewed size/concurrency requirements permit; compare that option with a tightly Film-owned extension only if row contention proves material. Do not create a competing generic project database. Personal viewport/selection/collapse preferences stay person-specific; graph editing visibility follows an explicit Film workspace policy.

Separate revisions by meaning: content/dependency edits increment Film content version and invalidate relevant approved quotes; graph coordinates/viewport changes increment only layout revision and must not modify an approved render plan. A dedicated layout revision avoids autosave continuously invalidating money approval. Existing server quote semantics remain conservative until a separately reviewed backend change can safely distinguish cosmetic edits. Never bypass `save_film` merely to retain an old quote.

Each bound node names an existing scene ID and, where appropriate, an immutable take/job/asset ID. Do not use node-array position as identity. Scene playback order remains `film_scenes.position`; dependency edges represent creative inputs only. Moving a scene in Timeline updates scene order and displayed order labels, not graph wires. Tidy/moving a card changes layout only. Connecting a frame to a scene updates its explicit supported input role, not when the scene plays. General multi-port edges are a future compatible extension to current one-input semantics, not implied already supported.

Adoption must preserve provenance and charge ownership: an existing completed asset/job adopted into Film is validated and referenced, not regenerated and not charged twice. A proposed attachment operation would create only the necessary server-authored association/version metadata under the existing Film identity, with a stable operation key. Its materialized result is visible in `film_json`. Uploaded/generated assets have existing `media_assets` IDs; signed URLs are ephemeral preview data and never persisted as identity. Selection of an older take must preserve newer history, update chosen version explicitly and invalidate the affected plan; it cannot be faked by replacing a node's local `jobId`.

Use one Film-aware draft/mutation controller shared by FilmCanvas, project-bound StudioCanvas and StudioTimeline, building on `useFilmProject`. Serialize writes, retain edits made in flight, and reuse version refusal/backoff/recovery states. After 409, freeze autosave and show base/local/server differences; offer reload or an explicit rebase with field-level conflicts. No automatic last-writer-wins or automatic replacement of someone's newer scene list. A preview refresh or late worker event cannot overwrite a newer accepted project revision.

Master-prompt planning creates a **reviewable draft** of nodes/scenes, with source attribution and unsupported/unpriced states. Acceptance saves draft content only. It must not start jobs, execute graph dependencies, publish or automatically approve quotes. Generating a single card continues through existing creative quote/start; whole-Film generation goes through existing Film quote/start. Do not fan out “generate all” into independent paid jobs while retaining a parent Film hold. Resolve parent/child ownership and reuse in the existing orchestrator before exposing such a control.

## Acceptance tests to specify before implementation

These are proposed tests, **not executed results**. Existing suites to extend include `films-store.test.tsx`, `films-ui.test.tsx`, `films-routes.test.ts`, `studio-timeline.test.ts`, `studio-timeline-ui.test.tsx` and graph/creative-route suites.

- Graph retains type/cycle validation and one-input replacement; layout order cannot reorder playback. Timeline reorder cannot reconnect dependencies.
- Project saved on device A reopens with identical graph, scene IDs, selected take versions and asset references on device B; personal viewport/selection remains scoped.
- Two concurrent edits at the same revision yield one accepted save and one conflict; local changes remain recoverable. No duplicate scene after a lost response/retry.
- Local edits made while saving survive response rebasing; out-of-order reads cannot regress saved versions. Expired session/rate limits pause safely; recovery cannot surface another person's pending data.
- Cosmetic graph move leaves content plan/quote unchanged under the approved split-revision contract; any model, prompt, dependency asset, take selection, chronology, duration or sound-content change stales approval. Expired/unavailable model fails explicitly with no substitution.
- A three-shot scene is ready only when every chosen-version shot has a completed highest-attempt take with a valid result; actual media duration determines measured labels/clock. Missing duration remains planned.
- Uploaded file and previously paid generation attach without another provider call or generation charge; foreign-org/deleted/wrong-kind/unmeasured references are refused. No client-authorable completed take.
- Double-click, keyboard repeat, view remount and timeout replay retain one idempotent start. Only explicit confirmation starts. Unknown outcome reconciles the original operation before another paid attempt.
- Whole-Film orchestration and independent card generation cannot reserve/capture twice for the same work. Unknown price blocks approval; quote changes require renewed approval.
- Undo affects drafts/layout, never refunds jobs, rewinds paid history or changes publication. Import preserves original local data until acknowledged and never auto-starts.
- Timeline-only unsupported trim/effect changes remain clearly unavailable or go to the real editor with explicit round-trip limits; no fabricated sync success.
- Responsive functional/visual QA at 375,390,430,768,1440,1920 widths; keyboard connections/reorder, focus-safe dialogs, touch scroll and accessible light/dark contrast. Screenshot review must preserve exact Nightshift brand assets.
