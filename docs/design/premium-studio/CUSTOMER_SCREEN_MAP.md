## Identity, shell and role contract

One customer implementation serves ordinary users and owner-in-Personal-Studio. The owner has a separate owner route namespace/surface selected from the **top-right N avatar dropdown only**. No investor role, duplicate owner creative workspace or duplicate customer project database. Ordinary users never receive an Owner Command menu item or owner financial payloads.

- Preserve the existing brand assets; screenshot N artwork is not a replacement logo. Sidebar navigation shows customer destinations, not Executive Overview/API Intelligence/Customers/Finance from the illustrative owner sidebar.
- Reuse `components/account/AccountMenu.tsx:34`: existing dialog focus management/Escape/Tab containment at66, fresh own-session account read at63, unknown values at115, settings/sign-out links at266. Reposition the existing trigger into the top-right header on customer desktop and mobile. Current desktop customer trigger is a sidebar card (`components/shell/CustomerSidebar.tsx:118`); the AccountMenu comment explicitly says customer phone has no trigger (`AccountMenu.tsx:16`). This is a concrete shell change, not a CSS-only promise.
- Existing `ViewModeToggle` inside AccountMenu (`AccountMenu.tsx:262`) is **Mobile/Desktop layout choice**, not Owner/Personal mode: `components/view-mode/ViewModeToggle.tsx:21` and71 write `ns_view` cookie and reload. Preserve this preference separately if retained. Do not repurpose it for owner authorization.
- Proposed owner mode entry uses server-derived owner capability from the existing access lookup, changes only the destination/shell, and never changes session or selected tenant. If mode persistence is needed, define an allowlisted presentation preference; it grants no access. User-edited cookie/query/localStorage must never enable owner APIs. Existing layout already checks authentication/onboarding at `app/(app)/layout.tsx:65`, operator lookup at95, MFA at115 and route redirects at125. Owner lookup failure is a retry/error state, not access or fabricated zeroes.
- Theme: reuse `ThemeToggle` currently at `AccountMenu.tsx:261`, refine to compact sun/moon icons with accessible names and selected state. Language: reuse locale controls at249; support English/Russian/Uzbek with dictionary parity (`lib/i18n/index.ts:1`). Sign-out keeps the existing `useSignOut` path. Keep username/photo/security settings under the same account implementation.
- Bell: reuse `components/shell/NotificationBell.tsx:53`; org-scoped notification read74, realtime101, existing mark-read RPC158 and mark-all170. No hardcoded red badge3. Unknown count differs from0. Search icon must either open an existing contextual search (Canvas search at `StudioCanvas.tsx:1184`) or be omitted/labelled unavailable; no fake universal search.
